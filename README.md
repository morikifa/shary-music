# SHARY

Android-приложение для совместного прослушивания музыки, которая уже есть на
телефоне. Двое и больше человек входят в одну комнату, слушают один трек
синхронно и переписываются в чате.

- Kotlin + Jetpack Compose + Material 3
- Media3 ExoPlayer, Room, DataStore, Coil
- Firebase Auth (анонимно) + Realtime Database + Storage

## Сборка

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

Требуется JDK 17 и Android SDK (compileSdk 34).

## Что реализовано в коде

- библиотека: добавление файлов системным пикером, обложки из тегов,
  лайки, удаление, поиск, фильтр «Понравившиеся»;
- плеер: пластинка с перемоткой вращением, ползунок, шаффл и повтор,
  сердечко, бегущие названия, лента обложек с «+»;
- комната 2–5 человек: код из 6 символов, пароль, роли, присутствие через
  `onDisconnect`, кик участника, смена пароля, удаление комнаты, чат;
- синхронизация воспроизведения: 150 мс допуск, мягкая коррекция до 800 мс;
  гость может скачать недостающий трек из Storage;
- настройки: рабочий эквалайзер на четырёх полосах, «скачивать только по
  Wi-Fi», светлая и тёмная темы;
- профиль: имя, аватар, статистика, истории прослушивания, выход.

> **Статус проверки.** Сборка и тесты в песочнице не запускались: в ней нет
> JDK, Android SDK и доступа к `dl.google.com`/`repo1.maven.org`. Поэтому
> список выше описывает реализованную логику, а не подтверждённый результат
> запуска. Первый шаг на машине с SDK — `./gradlew :app:assembleDebug`
> и `./gradlew :app:testDebugUnitTest`.

Не реализовано и зафиксировано в документах: фоновое воспроизведение через
`MediaSessionService`, UI-тесты, проверка версий Gradle/AGP.

## Структура

```
app/src/main/java/com/example/sharedmusic/
├── core/        константы приложения
├── domain/      чистая логика: код комнаты, чат, синхронизация, время
├── data/        Room, DataStore, ExoPlayer, Firebase
├── viewmodel/   состояние экранов
└── ui/          Compose-экраны, компоненты, тема, навигация
```

Подробности: `AGENTS.md`, `docs/`.
