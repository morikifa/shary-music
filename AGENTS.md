# AGENTS.md — постоянные правила проекта SHARY

Кратко: нативное Android-приложение на Kotlin + Jetpack Compose для совместного
прослушивания локальной музыки. Общение с владельцем продукта — по-русски,
документация — на английском (кроме этого файла и разделов для владельца).

## Что это за проект

SHARY позволяет двум и более людям, у каждого из которых есть свой аудиофайл,
слушать музыку синхронно в одной комнате и переписываться в чате.
Аудиофайлы не являются общим контентом сервиса: приложение воспроизводит
локальные файлы пользователя. Трек, которого нет у участника, можно скачать
по явному действию пользователя (см. `docs/DECISIONS.md`, D-002).

## Технологический стек (не менять без согласования)

Kotlin 2.0.20, Jetpack Compose (BOM 2024.09.00), Material 3, Navigation Compose,
Lifecycle ViewModel + StateFlow, Media3 ExoPlayer, Room, DataStore,
Firebase Auth (анонимный вход) + Realtime Database + Storage, Coil.
Версии зафиксированы в `gradle/libs.versions.toml`.

## Архитектура

```
ui/         Compose-экраны и компоненты: только отображение состояния и события
viewmodel/  Состояние экранов (StateFlow) и обработка событий
domain/     Чистая логика Kotlin без Android: код комнаты, чат, синхронизация, время
data/       Room, DataStore, ExoPlayer, Firebase (Realtime Database, Storage)
```

Правила:

1. Composable не обращается к Firebase, Room, файлам и сети напрямую.
2. Экран — функция от состояния: параметры вниз, события вверх.
3. Бизнес-логику держим в `domain/`, чтобы её можно было покрыть unit-тестами.
4. Все пользовательские строки — в `res/values/strings.xml`. ViewModel не
   получает `Context` ради текста: он отдаёт `MessageRes(id, args)`, а экран
   превращает его в строку (см. `docs/DECISIONS.md`, D-010).
5. Комментарии в коде — на русском и объясняют конкретную строку или блок.

## Обязательные проверки перед завершением задачи

- `./gradlew :app:assembleDebug` — сборка.
- `./gradlew :app:testDebugUnitTest` — unit-тесты домена.

Если среда не позволяет выполнить команду (нет JDK или Android SDK),
это нужно сообщить прямо, а не выдавать предположение за результат.

## Границы

- Секреты, ключи подписи и `keystore.properties` в репозиторий не попадают.
- `google-services.json` содержит только публичные идентификаторы клиента;
  этот файл в репозитории есть, service-ключей в нём нет.
- Правила безопасности Firebase обязательны до публикации: `docs/PLAY_RELEASE.md`.
