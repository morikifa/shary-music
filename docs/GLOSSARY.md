# Glossary

Short explanations of the concepts used in SHARY. Russian summary first,
English notes where useful.

## Kotlin

**`data class`** — класс, который хранит данные и автоматически получает
`equals`, `hashCode`, `copy` и `toString`. В SHARY так описаны все модели
(`Track`, `RoomMember`).

**`sealed interface` / `sealed class`** — ограниченный набор вариантов.
Например, `RoomSyncStatus` может быть только `Synced`, `CatchingUp`,
`TrackMissing` или `Offline`. Компилятор проверит, что `when` покрывает все
варианты — забыть состояние невозможно.

**`object`** — единственный экземпляр на процесс. Используется для чистой
логики без состояния: `RoomCode`, `ChatRules`, `SyncPolicy`.

**`suspend fun`** — функция, которая может приостановиться (например, ждать
ответа Firebase) и не блокирует поток.

**`coroutine`, `CoroutineScope`, `viewModelScope`** — лёгкий поток выполнения.
`viewModelScope` автоматически отменяет корутины, когда экран уничтожается,
поэтому утечек нет.

**`Flow` / `StateFlow`** — поток значений. `StateFlow` всегда хранит текущее
значение, поэтому новый подписчик сразу получает актуальные данные.

## Compose

**`@Composable`** — функция, которая описывает часть интерфейса. Она не
возвращает View, а «рисует» состояние.

**`remember`** — сохраняет значение между перерисовками. Без него переменная
обнулится при любом обновлении экрана.

**`mutableStateOf` / `by remember { mutableStateOf(...) }`** — изменяемое
состояние Compose: при изменении значения интерфейс перерисовывается сам.

**`LaunchedEffect(key)`** — запускает корутину при появлении экрана и при
изменении ключа. Так SHARY включает поиск и подписывается на чат.

**`Modifier`** — цепочка настроек внешнего вида и поведения: размер, отступы,
кликабельность. Читается сверху вниз, как список инструкций.

**`collectAsStateWithLifecycle()`** — превращает `StateFlow` в состояние
Compose и подписывается только пока экран виден на экране.

**`@Preview`** — предпросмотр Composable в Android Studio без запуска
приложения. В SHARY превью есть у каждого значимого экрана и состояния.

**`Canvas`** — область для ручной отрисовки. Так нарисованы виниловая
пластинка, логотип и индикатор воспроизведения: они чёткие на любом экране и
не требуют картинок.

**`graphicsLayer`** — слой для трансформаций (масштаб, прозрачность) без
пересчёта разметки.

## Архитектура SHARY

**UiState** — неизменяемый набор данных, который экран получает целиком.
Экран = функция от UiState и событий.

**ViewModel** — класс, который хранит состояние экрана, переживает поворот
экрана и вызывает слой данных.

**Repository / Store** — обёртка над источником данных (`TrackStore`,
`HistoryStore`, `RoomRemoteSource`). UI не знает, откуда пришли данные.

**ExoPlayer** — аудиодвижок Media3. Свой плеер не пишем.

**Realtime Database** — база Firebase с мгновенной синхронизацией и
`onDisconnect()` для присутствия участников.

**`ServerValue.TIMESTAMP`** — метка времени, которую ставит сервер. Нужна,
потому что часы двух телефонов всегда расходятся.

**`serverTimeOffset`** — поправка между часами устройства и сервером;
используется при расчёте ожидаемой позиции трека.

**Дрейф (drift)** — расхождение позиции трека между хостом и гостем в
миллисекундах. Пороги: меньше 150 мс — не трогаем, до 800 мс — мягкая
коррекция, больше — перескок.

**Слабый идентификатор трека (weak id)** — SHA-256 от имени файла, размера и
длительности. Не требует чтения содержимого файла, но может совпасть у разных
файлов с одинаковыми метаданными.

**`StringRes` и `MessageRes`** — идентификатор строкового ресурса вместо
готового текста. ViewModel не знает про `Context`, поэтому возвращает
`MessageRes(id, args)`, а экран превращает его в строку через
`context.getString`. Так текст остаётся в `strings.xml` и переводится.

**`ConnectivityManager` / `NetworkCapabilities`** — системный способ узнать,
какой сейчас тип сети. SHARY проверяет наличие транспорта `TRANSPORT_WIFI` или
`TRANSPORT_ETHERNET`, поэтому настройка «скачивать только по Wi-Fi» реально
запрещает загрузку в мобильной сети.

**`audioSessionId`** — номер аудиосессии ExoPlayer. По нему системный
`android.media.audiofx.Equalizer` подключается именно к нашему плееру:
номера известен только после старта воспроизведения, поэтому эквалайзер
подключается повторно при старте первого трека.

**`ListenDuration`** — результат в виде вариантов (`LessThanMinute`, `Minutes`,
`Hours`). Домен считает числа, а слова «мин» и «ч» подставляет экран из
ресурсов: поэтому длительность прослушивания переводится вместе с интерфейсом.
